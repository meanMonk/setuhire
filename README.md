# setuhire

Monorepo generated by `setup-project`. One shared Mongo on the `vaayu_db` network
(local via brew or docker infra, VPS via existing `vaayu_db` Mongo), Nginx routing
generated by `nginx-setup.ts`, and Scalar/OpenAPI docs on every Hono service.

## Layout

```
setuhire/
├── packages/
│   ├── web/        # frontend: setuhireweb (React + Vite + react-router-dom)
│   └── backend/    # API: setuhireapi (Hono, /docs + /openapi.json, Postgres + MinIO)
├── scripts/        # local helpers: db-info.sh, hosts-local.sh, run-agents.sh
├── docs/           # PRD + agent briefs (docs/agents) + seed CSVs
├── vps/            # VPS setup + deploy scripts + nginx
├── nginx-setup.ts  # generates per-app nginx site configs
├── docker-compose.yml        # all packages, join vaayu_db
└── docker-compose.infra.yml  # local postgres/mongo + minio on vaayu_db (VPS: skip)
```

## Quick start (local)

```bash
bash scripts/db-info.sh                # local brew DB endpoints (mongo :27017)
sudo bash scripts/hosts-local.sh       # one-time: mongo -> 127.0.0.1 for same URIs

# run everything (mongo + minio + apps) with docker:
docker compose -f docker-compose.infra.yml up -d   # infra, once
docker compose up -d --build                       # all apps

# or dev with pnpm (needs local Postgres + MinIO running):
cd packages/backend/setuhireapi && pnpm install && pnpm db:reset && pnpm dev   # http://localhost:3400/docs
cd packages/web/setuhireweb    && pnpm install && pnpm dev                    # http://localhost:3001
```

The canonical Mongo URI is the same for brew and docker:

```
MONGODB_URI=mongodb://<user>:<pass>@mongo:27017/<db>?authSource=<db>
```

After `hosts-local.sh`, `mongo` resolves to 127.0.0.1 locally (brew mongod, no auth);
inside docker it resolves to the `mongo` container on `vaayu_db`.

## API docs (Scalar + OpenAPI)

Every generated Hono service:

- `GET /docs`         — interactive Scalar UI
- `GET /openapi.json` — machine-readable spec
- `pnpm openapi`      — writes `openapi.json` to disk

## AI / LLM configuration

`setuhireapi` uses an LLM for parsing job descriptions & resumes and writing match
rationales. It is **optional** — with no key set, every feature falls back to a
deterministic parser/matcher.

Configure in `packages/backend/setuhireapi/.env` (see its `.env.example`):

| Var | Purpose | Default |
|-----|---------|---------|
| `LLM_PROVIDER` | Force a provider (`deepseek` \| `openrouter` \| `anthropic`) | auto-detect |
| `DEEPSEEK_API_KEY` | DeepSeek key | — |
| `DEEPSEEK_BASE_URL` | DeepSeek endpoint | `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | DeepSeek model | `deepseek-chat` |
| `OPENROUTER_API_KEY` | OpenRouter key | — |
| `OPENROUTER_BASE_URL` | OpenRouter endpoint | `https://openrouter.ai/api/v1` |
| `OPENROUTER_MODEL` | OpenRouter model | `deepseek/deepseek-chat` |
| `ANTHROPIC_API_KEY` | Anthropic key | — |
| `ANTHROPIC_MODEL` | Anthropic model | `claude-sonnet-4-20250514` |

Provider resolution (first key found): `deepseek` → `openrouter` → `anthropic`.
DeepSeek & OpenRouter use the OpenAI-compatible `/chat/completions` API (no extra
deps); Anthropic uses its native SDK. On a missing key or failed call, the service
falls back to the deterministic implementation.

### DeepSeek quick start

```bash
# packages/backend/setuhireapi/.env
DEEPSEEK_API_KEY=sk-…
# optional:
#   DEEPSEEK_MODEL=deepseek-chat      # deepseek-chat | deepseek-reasoner
#   LLM_PROVIDER=deepseek
```

Then `pnpm dev` and hit `POST /api/v1/jobs/parse-text` — with a key set the
response contains LLM-parsed fields; without one it returns the deterministic
result.

## Screens → app

```bash
screens2app --screens <dir> --app app1          # HTML mockups -> pages + tailwind theme
screens2app --screens <dir> --app app1 --llm    # LLM-enhanced (needs LLM_API_KEY/OPENROUTER_API_KEY)
```

## Nginx

```bash
npx tsx nginx-setup.ts                # regenerates nginx/conf.d/*.conf from .env + compose files
bash vps/nginx/setup-nginx.sh         # on the VPS: installs nginx + certbot, installs configs
```

## Deploy to a VPS

```bash
cp .env.example .env                  # set MONGO_/VA_DOMAIN etc.
# one-time as root:
bash vps/setup.sh                     # docker + vaayu_db network + nginx/certbot
# then:
bash deploy.sh                        # build + run everything on the VPS
bash deploy.sh packages/web/setuhireweb   # build + run one app
```

## Add apps / services

```bash
setup-project web=vite                # -> packages/web/app2
setup-project api=hono:invoices       # -> packages/backend/invoices
setup-project api=hono:mongo          # api with Mongo
```
